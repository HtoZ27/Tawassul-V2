## Supplementary activation and idempotency

After the main cycle, the source session exercised the session-pack path:

| # | Action | Observed result |
|---|---|---|
| 12 | `thread` `pack` from the source session, no `handoffId` | pack `72c63933…`, 46,418 bytes, warm for the source session |
| 13 | a literal identical `thread` `pack` retry | blocked by the host duplicate guard: “Cross-session duplicate of thread …”; no second pack (fixed after this run; see Findings) |
| 14 | `thread` `pack` with explicit `sessionID` | `reused=true`, “Already packed session … nothing was rebuilt.” |
| 15 | `thread` `revoke` of `72c63933…`, no confirm | `removed=false`, `revoked=true` (a warm pack is tombstoned, not deleted); `read` still returns 46,418 bytes; `list` shows `revoked transferred=0` |

The pack count stayed at one per session in every case. The idempotent branch is
reachable when the retry differs in its arguments; a byte-identical retry was
stopped by the host duplicate guard at the time of the run. That guard now
exempts the idempotent actions, so a byte-identical retry also reaches the
tool's reuse branch (proven by `scripts/prove-thread-tool.ts`).

## Measurements

- Overflow threshold: `128,000` window − `32,000` reserve − `1,024`
  minimum budget = `94,976` request bytes. The baseline was `19,233`; the
  overflowing request was `106,123`.
- Pack sizes: `H-001` was 906 bytes; the overflow pack was 36,614 bytes; the
  warm session pack was 46,418 bytes. All are below the 64,000-byte pack cap.
- Selection: the last unit and the 19,800-byte filler fit the 59,904-byte
  selection budget; the 66,000-byte filler was excluded. The pack retains the
  recent tail, not the whole transcript.
- The successor has no explicit model (`model: null` in the export); the
  `agent=tawa` default applies. `thread continue` does not switch models or
  agents on its own.

## Negative checks

- `thread read` with an invalid digest returned
  “Invalid digest: expected 64 lowercase hex characters.”
- `thread revoke` without `confirm` on a never-injected pack returned
  `confirmationRequired` and changed nothing.
- After the confirmed deletion, `thread read` returned
  “Context pack … is unavailable: … is not readable”.
- A byte-identical second `thread` `pack` call returned the host guard error
  “Cross-session duplicate of thread (…)” instead of the tool's “Already
  packed” response. The guard ran before the tool, so no duplicate pack was
  created; the tool's idempotent retry UX was not reachable for identical
  model retries. This is fixed: the guard now exempts `list`, `read` and `pack`,
  while `continue` and `revoke` remain guarded.

## Findings

1. Host duplicate guard vs tool idempotency (fixed). A byte-identical retry of
   `thread` `pack` was stopped by the cross-session duplicate guard before the
   tool could return its idempotent reuse result. The invariant still held: no
   duplicate pack was created. The fix adds
   `src/hooks/duplicate-guard.ts`, which exempts the idempotent
   `thread` actions (`list`, `read`, `pack`) from both the session deduplicator
   and the cross-session run log. `thread continue` and `thread revoke` stay
   guarded because they change state. `scripts/prove-thread-tool.ts` asserts
   the exemption, the unchanged guard for `continue`/`revoke`, and the
   unchanged same-session skip guard for other tools.

## Environment note

The first pack attempt pointed `TAWASSUL_HMAC_KEY_DIR` at a directory without a
`.tawassul-hmac-key` file. The plugin failed closed with
`HmacKeyUnavailableError`. Unsetting the variable let the plugin manage the key
under the isolated `HOME`, and the subsequent pack succeeded. The variable is
read-only by design: when set, it must point at an existing key file.

## Conclusion

The final handoff → pack → continue → injection → revoke cycle passes on a live
2.2.2 host with full isolation. The measured overflow gate, the flat transfer,
the tombstone-after-injection path and the destructive pre-injection path all
behave as specified. The supplementary activation, idempotent-reuse and
warm-revoke checks also pass. The duplicate-guard finding is fixed in code and
covered by the thread-tool proof; the live replay of step 13 was not repeated
after the fix.

Why it exists

Long sessions lose structure. One opinion hides disagreement.

A single assistant drifts: tasks blur, decisions lose their evidence, and the reason a change was accepted disappears into the transcript. Tawassul keeps that structure outside the model — owners, handoffs, goal items, and evidence — so a later turn can inspect what happened instead of guessing.

Parallel specialists are not automatically better. They cost more and they can disagree. Tawassul makes the disagreement visible, records the bill, and lets the coordinator decide. The parallel scenario on this site shows both the consensus and the dissent.

The rule the demo follows

Every claim is tied to a recorded event. Model names are dated capture facts, not a catalog. The roster is a generated example, not a personal configuration. When a mechanism fails, the scenario is dropped rather than illustrated.

Install

Three supported paths.

Use project scope for a local workspace. The release installer verifies the bundle and never edits your OpenCode configuration. The installation reference is the source of truth for every path and flag.

Release installer · project

one workspace
sh install.sh --project <dir> --dry-run
sh install.sh --project <dir>

Loads only inside that workspace.

Release installer · global

every workspace
sh install.sh --global --dry-run
sh install.sh --global

Writes the plugin and runtime under the user config root.

Source checkout

build from source
nvm use
npm install
npm run build

Then open the workspace; the host discovers the plugin.

One setting lives in the app

Open Settings → General and turn on Show agent. The composer then carries the agent selector, so a session can run as a derived specialist. While it is off, the app stays on the Build agent.

# Recovery — 2026-10-25 desktop DB split

Status: resolved on 2026-10-25. Read this before touching session databases or
the predictive router.

Related records: R-003 (incident), R-004 (fix), R-005 (decision), R-006 (note).
They are available after a restart through `record(list: true)`.

## Symptom

- OpenCode Desktop showed "cannot find this session" for two tabs:
  - `ses_e91b3b15effdZ7ShEJbuqcgFYu` — 824 messages
  - `ses_e919e1013ffel2nffimAkPAr0F` — 118 messages
- `~/.local/share/opencode/log/opencode.log` returned 404 for both IDs.
- `~/.config/ai.opencode.desktop/drafts.sqlite` still listed both IDs, so the
  tabs were intact; only the data lookup failed.

## Root cause

Three host databases existed, and the desktop was not reading the one that
contained the sessions.

| Writer | Database |
| --- | --- |
| Desktop sidecar | `~/.local/share/opencode/tawassul-v2/opencode.db` |
| Shared CLI / bare host | `~/.local/share/opencode/opencode.db` |
| Pinned launcher | `~/.local/share/tawassul-v2/opencode-v2.db` |

The sessions lived in the shared DB; the desktop read the sidecar. No rows were
lost. This was a split-brain DB path, not corruption.

`session_v2` has the same column set in both DBs but a different physical order
(`time_idle`, `time_viewed`, `idle_outcome` sit in different positions). Never
use `INSERT INTO ... SELECT *` across these DBs.

## Recovery

The desktop service was not stopped: it also served the live conversation, and a
second host or `session import` would contend on the same project state.

1. Back up every DB with SQLite's backup API, not `cp`:

```bash
mkdir -p ~/.local/share/opencode-backups/20261025
sqlite3 ~/.local/share/opencode/opencode.db \
  ".backup '$HOME/.local/share/opencode-backups/20261025/shared-pre-recovery.db'"
sqlite3 ~/.local/share/opencode/tawassul-v2/opencode.db \
  ".backup '$HOME/.local/share/opencode-backups/20261025/sidecar-pre-recovery.db'"
sqlite3 ~/.local/share/tawassul-v2/opencode-v2.db \
  ".backup '$HOME/.local/share/opencode-backups/20261025/launcher-pre-recovery.db'"
```

2. Export the session and prove the round trip on a throwaway DB:

```bash
opencode session export ses_e91b3b15effdZ7ShEJbuqcgFYu > /tmp/tw-dbcheck/ses_e91b.json
OPENCODE_DB=/tmp/tw-dbcheck/throwaway.db \
  opencode session import --standalone /tmp/tw-dbcheck/ses_e91b.json
```

The import kept the same session ID and all 824 messages. The exported file was
5,051,763 bytes. `--standalone` plus `OPENCODE_DB` keeps the round trip off the
live service; never run a plain `session import` while the desktop is open.

3. Merge into the sidecar with an explicit column list. `project_id` must point
   at the sidecar's project row for `/home/htoz/Desktop/Tawassul V2`:

```sql
ATTACH DATABASE 'file:/tmp/tw-dbcheck/shared.db?mode=ro' AS src;
BEGIN IMMEDIATE;
INSERT INTO session_v2 (id, project_id, workspace_id, parent_id, fork_session_id,
  fork_boundary, slug, directory, path, title, version, share_url,
  summary_additions, summary_deletions, summary_files, summary_diffs, metadata,
  cost, tokens_input, tokens_output, tokens_reasoning, tokens_cache_read,
  tokens_cache_write, revert, permission, agent, model, time_created,
  time_updated, time_idle, time_viewed, idle_outcome, time_compacting,
  time_archived, time_suspended, resume_attempts)
SELECT id,
  (SELECT id FROM project WHERE worktree = '/home/htoz/Desktop/Tawassul V2' LIMIT 1),
  workspace_id, parent_id, fork_session_id, fork_boundary, slug, directory,
  path, title, version, share_url, summary_additions, summary_deletions,
  summary_files, summary_diffs, metadata, cost, tokens_input, tokens_output,
  tokens_reasoning, tokens_cache_read, tokens_cache_write, revert, permission,
  agent, model, time_created, time_updated, time_idle, time_viewed,
  idle_outcome, time_compacting, time_archived, time_suspended, resume_attempts
FROM src.session_v2
WHERE id IN ('ses_e91b3b15effdZ7ShEJbuqcgFYu', 'ses_e919e1013ffel2nffimAkPAr0F');
INSERT INTO session_message (id, session_id, type, seq, time_created, time_updated, data)
SELECT id, session_id, type, seq, time_created, time_updated, data
FROM src.session_message
WHERE session_id IN ('ses_e91b3b15effdZ7ShEJbuqcgFYu', 'ses_e919e1013ffel2nffimAkPAr0F');
COMMIT;
```

The source was a snapshot at `/tmp/tw-dbcheck/shared.db`, not the live shared DB,
so a concurrent writer cannot move rows under the transaction.

4. Verify:

```bash
sqlite3 ~/.local/share/opencode/tawassul-v2/opencode.db "PRAGMA quick_check;"
sqlite3 ~/.local/share/opencode/tawassul-v2/opencode.db \
  "SELECT session_id, count(*) FROM session_message
   WHERE session_id IN ('ses_e91b3b15effdZ7ShEJbuqcgFYu','ses_e919e1013ffel2nffimAkPAr0F')
   GROUP BY session_id;"
```

Expected: `ok`, `824`, `118` (942 total).

5. Verify through the live API. Basic auth user is `opencode`; the password is in
   `~/.local/state/opencode/service.json`:

```bash
PW=$(jq -r .password ~/.local/state/opencode/service.json)
BASE=$(jq -r .url ~/.local/state/opencode/service.json)
curl -s -o /dev/null -w '%{http_code}\n' -u "opencode:$PW" \
  "$BASE/api/session/ses_e91b3b15effdZ7ShEJbuqcgFYu"
curl -s -o /dev/null -w '%{http_code}\n' -u "opencode:$PW" \
  "$BASE/api/session/ses_e91b3b15effdZ7ShEJbuqcgFYu/message"
```

Expected: `200` for both sessions and both endpoints.

6. Reopen the desktop tabs. The session list reads the sidecar; the recovery
   itself did not require a desktop restart.

## Multi-project hardening

The same investigation found the only writable cross-project surface:
`predictive-router.json` was global. Two live projects rewrote each other every
five minutes (last-writer-wins, no lock).

| Change | File |
| --- | --- |
| `scopedStatePath(base, scope, fileName)` | `src/utils/state-paths.ts` |
| Router writes to `<project>/.opencode/predictive-router.json`; the global file is a read fallback only | `src/bootstrap/service-factory.ts` |
| `ServiceIndex` fallback trust/cost scoped to `resolveRuntimeStateDir` | `src/services/service-index.ts`, `src/bootstrap/tool-registry.ts` |
| `health` reports scope, state paths, router paths, DB path, expected DB, match status | `src/tools/tawa/health.ts` |
| `npm run doctor` checks symlink, scope, DB isolation, session counts, orphan servers | `scripts/doctor-v2.sh`, `package.json` |
| Two router assertions | `scripts/prove-state-namespace.ts` |
| Operator docs | `README.md` |

Live evidence: the project router appeared at 04:55:04 local, the global file
stopped at 04:53:26, and the project file kept updating every five minutes.
`opencode reload` then rebuilt the plugin without stopping the service:
`INIT_AUDIT ... "health":"healthy"`, `42 schemas`, `42 tools`, pid `704051`
unchanged.

## If a session is missing again

Do not delete or re-import anything first. Count sessions in each DB:

```bash
npm run doctor
```

Then compare the desktop sidecar, the shared DB, and the launcher DB. If the
session exists in one DB and the desktop reads another, this is the same split:
take fresh `.backup` files and repeat the merge with explicit column lists.

## Free-limit note

The restored sessions end with `provider.free-limit` failures from
2026-10-24 19:50-19:52 local, not from the plugin:

- `ses_e91b...` used `opencode/beam-free` (4 failures).
- `ses_e919...` used `opencode/big-pickle` (2 failures).

Switch those sessions to a model with quota, for example
`opencode/deepseek-v4.1-flash-free` (working on 2026-10-25). Also note that
`opencode web` is not a subcommand in host 2.1.4; the CLI treats `web` as a
directory and fails with `chdir ENOENT`. Use `opencode serve` for the v2
API/web server or `opencode pair` for browser links.
